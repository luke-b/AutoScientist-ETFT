# Plan: Milestone 2.2 - Reverse-Engineering the TinyML Trajectory

## 1. Problem statement and business rationale
The project roadmap dictates that we must now support regression on standard tabular ML models, specifically targeting TinyML performance metrics like accuracy and memory footprint. This is essential for the AutoScientist-ETFT to reverse-engineer algorithmic progression towards lightweight SOTA models.

## 2. Current behavior and target behavior
- Current behavior: `run.py` validates generated code using a restricted execution environment which currently blocks imports like `pandas`, `datasets`, and some standard library modules, preventing the evaluation of datasets loaders like `corpus/healthcare_loader.py` or equivalent SOTA tabular model scripts.
- Target behavior: The `allowed_packages` whitelist in `config.yaml` includes the necessary packages. A standard tabular SOTA script for `health_edge` is available and acts as the start of the regression trajectory. The pipeline successfully builds a trajectory.

## 3. Requirement and GAP references
Addresses the gap for Milestone 2.2: Reverse-Engineering the TinyML Trajectory, allowing `run.py` to handle tabular ML models that emit TinyML metrics.

## 4. Proposed architecture and design decisions
- Modify `config.yaml` to include `pandas`, `datasets`, `urllib`, `io`, `csv`, `os`, `sys`, and `corpus` in `allowed_packages`.
- Provide the seed code at `corpus/seed_models/health_edge_sota.py` containing a tabular TinyML model training script (using a Random Forest or lightweight equivalent for the `health_edge` target) which prints `METRIC:` formatted lines.
