# 2026-11-02 Execution Plan

## 1. Problem statement and business rationale
The project needs a robust local sandbox for executing TinyML models on CPU-only hardware to simulate edge devices. This is the first milestone in the Development Roadmap.

## 2. Current behavior and target behavior
- **Current:** Sandbox exists (`etft/sandbox.py`) but does not explicitly enforce edge-device memory constraints or include edge ML compilation tools in its environment.
- **Target:** Sandbox enforces strict memory constraints and supports tools like TFLite Micro.

## 3. Requirement and GAP references
- REQ-ROADMAP-1.1
- GAP-0001

## 4. Scope, non-goals, and assumptions
- **Scope:** Modify `etft/sandbox.py` to enforce memory limits in `DockerSandbox`.
- **Non-goals:** Building the full pipeline, executing real data yet.
- **Assumptions:** Docker is available or mockable for testing.

## 5. Proposed architecture and design decisions
- Add memory limit configuration to `DockerSandbox`.

## 6. Affected modules and interfaces
- `etft/sandbox.py`
- `tests/test_sandbox.py` (assuming it exists)

## 7. Data and infrastructure implications
- Docker container execution will have stricter memory limits.

## 8. Implementation milestones
1. Update `DockerSandbox` configuration.
2. Update/create tests to verify memory limits.
3. Pre-commit checks.
4. Finalize evidence and commit.

## 9. Acceptance criteria with stable IDs
- **AC-1:** `DockerSandbox` initialization accepts a memory limit parameter (e.g., `mem_limit`).
- **AC-2:** `DockerSandbox` applies this memory limit when running containers.
- **AC-3:** Tests verify the memory limit is passed to the Docker engine.

## 10. Tests and verification commands
- `pytest etft/tests/test_sandbox.py`
- `ruff check etft/sandbox.py`

## 11. Required external acceptance evidence
- None (internal component).

## 12. Security and regression risks
- Container execution failure if memory is too low.

## 13. Rollback or recovery approach
- Git revert.

## 14. Definition of Done
- Code implemented, tests pass, documentation updated.

## 15. Explicit stop and escalation conditions
- If Docker is strictly required and not available in the environment, escalate.
