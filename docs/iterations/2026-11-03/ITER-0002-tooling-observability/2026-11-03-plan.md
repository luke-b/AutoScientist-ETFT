# 2026-11-03 Execution Plan

1. **Problem statement and business rationale:**
   To fully support the TinyML for Global Health proof-of-concept, the framework must track hardware-centric metrics (FLOPs, parameter count, binary size) to evaluate candidate models effectively under severe memory constraints.

2. **Current behavior and target behavior:**
   Currently, the system tracks general experiment metrics like success rate but lacks visibility into hardware costs. The target behavior adds logging for FLOPs, parameters, and binary size to MLflow summaries and displays them in the `etft-report` CLI.

3. **Requirement and GAP references:**
   REQ-ROADMAP-1.2, GAP-0002.

4. **Scope, non-goals, and assumptions:**
   Scope includes updating `etft/run_logger.py` and `reporting.py`. It does not include changing how agents collect these metrics (assumes agents will push them into `ExperimentResult.metrics`).

5. **Proposed architecture and design decisions:**
   Modify `_mlflow_log_summary` to iterate through known hardware metrics if they exist in the nested `metrics.metrics` dictionary. Update `reporting.py` `_to_report_rows`, `_print_rich_table`, and `_print_plain_table` to include these.

6. **Affected modules and interfaces:**
   `etft/run_logger.py`, `reporting.py`.

7. **Data and infrastructure implications:**
   No infrastructure changes. CLI users will see new columns.

8. **Implementation milestones:**
   - Update `run_logger.py`.
   - Update `reporting.py`.

9. **Acceptance criteria with stable IDs:**
   - AC-1: `etft-report` outputs columns for FLOPs, Params, and Bin Size.
   - AC-2: `run_logger.py`'s `_mlflow_log_summary` logs means for these metrics if available.

10. **Tests and verification commands:**
    - `pytest`
    - `python reporting.py` against a dummy run directory.

11. **Required external acceptance evidence:**
    CLI output screenshot / textual capture.

12. **Security and regression risks:**
    Low risk. Formatting errors in reporting could occur if values are unexpected types (e.g., None).

13. **Rollback or recovery approach:**
    Revert changes to `reporting.py` and `etft/run_logger.py`.

14. **Definition of Done:**
    ACs pass, documentation is written.

15. **Explicit stop and escalation conditions:**
    Escalate if the `MetricsCollector` structure differs radically from assumptions.
