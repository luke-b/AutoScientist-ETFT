## Problem statement and business rationale
The project needs to move to Phase 3: "GPU-Poor" ETFT Deployment, starting with Milestone 3.1: Pareto Optimization Calibration. This involves updating the Pareto delta analysis to track activation-related components and tuning the Probabilistic Heuristic Filter (`D_Perf`) to automatically reject algorithm candidates that exceed a memory threshold (256 KB) required for TinyML edge devices.

## Current behavior and target behavior
- **Current Behavior**:
  - The `_COMPONENT_PATTERNS` in `analysis/pareto_delta/delta_calculator.py` tracks changes in convolutions, classes, functions, etc., but doesn't explicitly look for activation functions (e.g., ReLU, Sigmoid).
  - The Probabilistic Heuristic Filter's `DatasetBuilder` simply marks candidates as passed (0) if they don't fail standard validation, regardless of how much memory they consume.
- **Target Behavior**:
  - Update `_COMPONENT_PATTERNS` to include patterns for activation functions (e.g., `relu`, `sigmoid`, `activation`) so that activation memory bottlenecks are explicitly tracked in the Pareto analysis.
  - Modify `corpus/performance_estimator/dataset_builder.py` so that a `ValidationResult` is labeled as a failure (label = 1) if its `peak_memory_mb` exceeds `0.25` MB (256 KB), thereby training the filter to reject memory-heavy candidates.
