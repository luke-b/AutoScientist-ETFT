# Increment Report

**Iteration ID:** ITER-0007-arl-empirical-micro-experiments
**Date:** 2026-11-11
**Base Commit:** (Working tree prior to changes)

## Delivered Capability and User Value
The Agentic Research Loop (`run_arl.py`) and empirical micro-experiment designer (`ExperimentDesigner`) are now fully aware of the TinyML constraint. Specifically, when executed with `--domain tinyml`, the LLM prompt generated for designing experiments explicitly instructs the model to keep the peak memory footprint under the critical 256KB threshold. This saves cycles by ensuring generated micro-experiment code is mindful of edge hardware constraints before it goes through validation.

## Previous and New Behavior
- **Previous:** `ExperimentDesigner` used a generic prompt that did not restrict or inform the generated script about memory sizes, making it likely to generate high-footprint code for TinyML problems.
- **New:** `ExperimentDesigner` now reads the `domain` argument (propagated down from the ARL CLI entrypoint). When this domain is `tinyml`, it augments the prompt dynamically with the line: `"Ensure the peak memory footprint stays under the 256KB constraint."`

## Expected Results
- `python -m agents.run_arl --bottleneck depthwise_conv --domain tinyml` routes the domain to the literature searcher (producing tailored results) and to the empirical designer (yielding memory-constrained architectures).

## Setup and Prerequisites
- The environment requires `pip install python-dotenv httpx`.
- An LLM API endpoint must be running or configured appropriately using the `PROXY_LLM_BACKEND` variables so the empirical proxy connection can complete successfully. (e.g. `docker compose -f docker/docker-compose.yml up -d` configured).

## Known Limitations
- If the proxy backend is unreachable, the experiment loop correctly intercepts the connection failure, preventing it from producing unvalidated results, but stopping the process (exit code 1 or HTTP 502/111).
